# 产品比较试点：权威资料核对

## 试点产品与版本对应

本地开发库挑出的两个候选记录是 `1715302322424270849`（好医保·长期医疗）和 `1716769693731250178`（好医保·长期医疗（20年版））。本地 `publish_number` 是平台内部值，不能替代保险条款备案编号。

人保健康官网的网销产品清单将“好医保·长期医疗”对应到**人保健康悠享保互联网医疗保险**（2023 医疗保险 013 号，条款内部编号 `9100015834`），将“好医保·长期医疗（20年版）”对应到**人保健康悠优保互联网医疗保险（费率可调）**（2023 医疗保险 015 号，条款内部编号 `9100015852`）。但官网还列有 2021 年的同名或近似销售名称版本，因此本地记录只有在补入备案编号/条款文件引用后才能被唯一识别。

核对发现，本地第二个候选的自由文本年龄描述与 2023 年官方悠优保条款不一致。两个本地记录均未存备案编号、条款版本、审核状态或资料来源定位。因此这两个 ID 只作为开发试点候选，**不作为已确认可面向客户发布的产品事实**；不要把本页摘要导入生产目录。

## 接入与验收结论

Java 推荐响应已经有版本化事实及 `KNOWN`、`NOT_PROVIDED`、`NOT_APPLICABLE` 状态；本次补上 Python 每轮工具结果收集和 Java 到客户 DTO 的结构化透传，包含推荐状态、目录/规则版本、产品版本和类型化比较事实。模型生成的自然语言不能覆盖这些字段。

本地数据库没有经审核发布的这两款产品事实；当前也没有产品资料草稿/审核/发布管理接口。因此本次不能诚实地声称真实业务数据已通过 Java API 发布并完成端到端客户比较。可执行的验收范围是 Python 工具/响应契约和 Java DTO 映射；真正上线该产品比较前，需先由产品负责人核准两个本地 ID 对应的备案版本，录入来源和有效期，审核后发布快照。
